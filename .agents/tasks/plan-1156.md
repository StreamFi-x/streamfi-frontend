# Implementation Plan: Issue #1156 — Exchange-rate lock at tip-initiation time

## Overview

This plan implements exchange-rate locking for the StreamFi tipping system to prevent price-move exploitation. When a user initiates a tip, the system will generate a temporary quote with a locked XLM/USD exchange rate, preventing price slippage attacks where the quoted rate at UI time differs from the rate used at settlement time.

## Design Decisions

1. **Quote Token Generation**: Use `crypto.randomBytes(32).toString('hex')` for secure, 64-character hex tokens (similar to recovery tokens in `lib/auth/wallet-recovery.ts`). This is non-collision and non-guessable.

2. **Quote Expiry**: 5-minute TTL for all quotes. This is long enough for a user to read and confirm a tip (UX best practice), short enough to mitigate stale-rate risk in volatile markets.

3. **Rate Source**: Reuse the existing `GET /api/prices/xlm` endpoint (in `app/api/prices/xlm/route.ts`), which fetches from Binance and caches for 60s. This avoids external API call fragmentation and leverages proven fallback logic.

4. **Quote Storage**: New `exchange_rate_quotes` table tracks issued quotes with issued_at, expires_at, and consumed_at to enforce one-time use and enable audit trails.

5. **Quote Validation**: The tip submission route (`/api/tips/send`) accepts `quote_token` and validates that the quote exists, has not expired, matches the tip amount, and has not yet been consumed. Upon tip confirmation, mark the quote as consumed.

6. **Client-Side**: TipModal calls `GET /api/tips/get-quote` when user enters/confirms an amount, displays the locked rate with a countdown timer, and re-quotes on expiry or manual refresh.

## Files to Create and Modify

### 1. Database Migration

**File**: `db/migrations/20261020120000_exchange_rate_quotes.sql`

SQL content:
```sql
-- Exchange-rate quotes: lock rates at tip initiation to prevent price-move exploitation
-- Supports 5-minute quote lifetime with audit trail (issued, consumed, expired)

CREATE TABLE IF NOT EXISTS exchange_rate_quotes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  creator_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  quoted_rate NUMERIC(20, 10) NOT NULL,
  quoted_xlm_amount NUMERIC(20, 7) NOT NULL,
  fiat_amount_cents INTEGER NOT NULL,
  quote_token TEXT UNIQUE NOT NULL,
  issued_at TIMESTAMPTZ DEFAULT NOW(),
  expires_at TIMESTAMPTZ NOT NULL,
  consumed_at TIMESTAMPTZ,
  status TEXT NOT NULL DEFAULT 'issued' CHECK (status IN ('issued', 'consumed', 'expired')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_exchange_rate_quotes_creator_id 
  ON exchange_rate_quotes(creator_id);

CREATE INDEX IF NOT EXISTS idx_exchange_rate_quotes_quote_token 
  ON exchange_rate_quotes(quote_token) 
  WHERE status = 'issued';

CREATE INDEX IF NOT EXISTS idx_exchange_rate_quotes_expires_at 
  ON exchange_rate_quotes(expires_at) 
  WHERE status = 'issued';

COMMENT ON TABLE exchange_rate_quotes IS 'Time-limited exchange rate locks for tip transactions, preventing price-slip exploitation';
COMMENT ON COLUMN exchange_rate_quotes.quote_token IS '64-char hex token, unique and non-guessable, used to redeem quote at payment time';
COMMENT ON COLUMN exchange_rate_quotes.quoted_rate IS 'XLM/USD spot rate (e.g., 0.45) locked when quote issued';
COMMENT ON COLUMN exchange_rate_quotes.quoted_xlm_amount IS 'XLM amount (e.g., 10.5000000) locked in this quote';
COMMENT ON COLUMN exchange_rate_quotes.fiat_amount_cents IS 'USD cents equivalent (e.g., 472 = $4.72) locked in this quote';
COMMENT ON COLUMN exchange_rate_quotes.consumed_at IS 'When this quote was redeemed via tip submission; null if not yet consumed';
COMMENT ON COLUMN exchange_rate_quotes.status IS 'issued=active, consumed=tip confirmed, expired=TTL exceeded or marked stale';
```

**Verification**: After applying migration, run `npm run db:migrate` and confirm the `exchange_rate_quotes` table exists with correct columns/indexes.

### 2. New GET /api/tips/get-quote Route

**File**: `app/api/tips/get-quote/route.ts`

Functionality:
- Accept query params: `destinationPublicKey` (recipient wallet), `amount` (XLM), `creatorId` (optional, for multi-creator flows)
- Fetch current XLM/USD rate from `GET /api/prices/xlm` (reuse existing rate-fetch logic)
- Validate amount is between MIN_TIP_AMOUNT and MAX_TIP_AMOUNT
- Generate secure quote_token using `crypto.randomBytes(32).toString('hex')`
- Insert row into `exchange_rate_quotes` with 5-minute expiry
- Return JSON: `{ quote_token, quoted_rate, quoted_xlm_amount, fiat_amount_usd, expires_at }`

Error handling:
- 400 if amount invalid or out of range
- 400 if destinationPublicKey invalid format
- 503 if price fetch fails (same fallback as TipModal already has)

**Verification**: `npm run test -- app/api/tips/get-quote` or manual test with `curl http://localhost:3000/api/tips/get-quote?destinationPublicKey=G...&amount=10`.

### 3. Modify POST /api/tips/send Route

**File**: `app/api/tips/send/route.ts`

Changes:
- Add `quote_token` to request body validation schema (required string)
- After validating amount/recipient keys, query `exchange_rate_quotes` table:
  - Fetch row by quote_token WHERE status = 'issued'
  - Verify quote has not expired: `expires_at > NOW()`
  - Verify quote amount matches request amount: `quoted_xlm_amount = ${amount}`
  - If validation fails, return 400 "Invalid or expired quote"
- After successful Stellar transaction submission and ledger confirmation:
  - Update quote row: SET `status = 'consumed', consumed_at = NOW()` WHERE quote_token = ${quoteToken}
  - This prevents reuse of the same quote

export async function markExpiredQuotes(): Promise<number> {
  const { rowCount } = await sql`
    UPDATE exchange_rate_quotes

    WHERE status = 'issued' AND expires_at < NOW()
  `;

}

## Edge Cases & Error Handling

- **Quote expires during tip submission**: Catch this gracefully; route returns 400 "Quote expired", user retries with fresh quote.
- **Concurrent quote usage**: Database UNIQUE constraint on quote_token prevents double-spend; second submission sees consumed_at already set.
- **Price service unavailable**: Reuse existing fallback in `/api/prices/xlm` (returns last known price or 0.08 fallback). Quote succeeds with fallback rate.
- **User cancels mid-flow**: Unconsumed quotes remain in DB with `status='issued'` and eventually `status='expired'`. No cleanup needed immediately; periodic job handles it.
- **Session timeout between quote and submission**: Quote is still valid if within 5 min TTL. User refreshes page, component fetches new quote, proceeds normally.
