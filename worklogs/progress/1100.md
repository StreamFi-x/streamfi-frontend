# Issue #1100: Channel Points Redemption Catalog

## Branch: feat/channel-points-system
## Status: In Progress

## Implementation Plan

### Overview
Manage a creator's catalog of channel-point redemption items with CRUD operations and a 30-item limit.

### Requirements
1. **GET** `?creator_id` - Returns catalog items with fields: `{ id, name, cost, cooldown_seconds, enabled }`
2. **POST** - Creates a new catalog item
3. **PATCH** - Updates an existing item
4. **DELETE** - Removes an item
5. Cap catalog at 30 items maximum
6. Tests covering lifecycle and cap enforcement

### Scope Constraints
- All files must live inside `app/api/routes-f/`
- No modifications, imports from, or additions to `lib/`, `utils/`, `types/`, `components/`, or anywhere outside `app/api/routes-f/`
- If shared logic is needed, duplicate it within the subfolder

### Data Models
```typescript
interface CatalogItem {
  id: string;
  creator_id: string;
  name: string;
  description?: string;
  cost: number;              // Channel points cost
  cooldown_seconds: number;  // Cooldown between redemptions
  enabled: boolean;
  created_at: Date;
  updated_at: Date;
}

interface CatalogResponse {
  items: CatalogItem[];
  total: number;
  limit_reached: boolean;  // True if at 30 items
}
```

### Validation Rules
1. `name`: Required, max 100 characters
2. `cost`: Required, positive integer, min 1, max 1000000
3. `cooldown_seconds`: Required, min 0 (no cooldown), max 86400 (24 hours)
4. `enabled`: Boolean, defaults to true
5. Creator must have less than 30 items to create new ones

### Test Coverage Requirements
- ✓ GET returns empty array for new creator

- ✓ POST creates item successfully

- ✓ PATCH updates item fields
